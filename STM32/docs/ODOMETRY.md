# 里程计与定距控制

2026-11-17 起，STM32 用三轮反馈估计平移速度、用 IMU 提供航向，现有 `Chassis_Distance_Start()` 改为按估计位移闭环控制。底盘任务、八向枚举、三轮几何、MIT 发送、航向 PID 和 USB 协议沿用原结构。本轮未烧录或执行实车运动。

## 来源与本车适配

参考官方 ros-controls/ros2_controllers 的 [omni_wheel_drive_controller](https://github.com/ros-controls/ros2_controllers/tree/62af79e4788adaf4718491968c3f8fcc632af265/omni_wheel_drive_controller)，固定提交 `62af79e4788adaf4718491968c3f8fcc632af265`（2026-11-12）。该模块使用轮速反馈正解车体速度，并在平面内积分位姿；[上游实现](https://github.com/ros-controls/ros2_controllers/blob/62af79e4788adaf4718491968c3f8fcc632af265/omni_wheel_drive_controller/src/odometry.cpp)及 [package.xml](https://github.com/ros-controls/ros2_controllers/blob/62af79e4788adaf4718491968c3f8fcc632af265/omni_wheel_drive_controller/package.xml)标注 Apache-2.0，作者 Aarav Gupta。

本仓库参考平面刚体圆弧积分原理自行适配纯 C 实现，没有移入上游函数、Eigen 矩阵求解或 ROS 运行依赖。三轮正解复用 `Motor_Chassis_Forward()`；平移用相邻有效组的速度梯形积分，航向采用已有 INS 解算并展开 ±180° 跨界，按该段航向变化进行圆弧积分。它是轮速平移与 IMU 航向组合，不是 EKF，也没有外部绝对位置观测。

| --- | --- |
| [chassis_odometry.h](../project/Core/Algorithm/Chassis/chassis_odometry.h)、[chassis_odometry.c](../project/Core/Algorithm/Chassis/chassis_odometry.c) | 纯 C 位姿状态、有效样本积分和基线管理 |

## 坐标、采样与有效性

车体 `vx` 向前、`vy` 向左，单位 m/s；轮角速度单位 rad/s；航向俯视逆时针为正。反馈先按原电机方向和齿比换算成几何轮速，再调用三轮正解。轮半径仍为 35 mm，中心到轮接地点仍为 108 mm。位移在 INS 零航向所定义的固定平面坐标系中累计，不能直接当作相机坐标或场地图坐标。

底盘任务在短临界区内一次复制三轮的速度、ID、状态、接收时间和序号。只有三轮各自的序号都相对上次接受组更新，才有新的积分组；一轮高频重复上报不能代替另外两轮的新证据。三轮仍非硬件同步采样，临界区只保证读取过程不被 CAN 接收更新打断。

| 条件 | 处理 |
| --- | --- |
| 三轮反馈 | ID、状态和数值须有效，均未超过 30 ms |
| IMU | 采用同一次 INS 解算快照，样本未超过 20 ms |
| 积分时间 | 使用实际采样间隔，单步最长 50 ms；过长的未知路段不截短后冒充有效积分 |
| 尚未形成完整新组 | 不把重复反馈当成新的位移样本 |
| 反馈/姿态失效或时间断档 | 标记里程计无效，丢失期间不补积分 |
| 恢复首个有效组 | 仅建立新的速度、航向与时间基线，后续有效组再累计位移 |

恢复后不能还原断流期间已经发生的真实位移。`valid` 表示当前估计可用于控制，不保证整段历史轨迹没有缺失。定距运行期间失效会进入故障停车，恢复数据不会自动续跑原动作。

## 读取与重置接口

接口和 `Chassis_Loop()` 均由同一底盘控制任务调用；本轮没有增加供其他任务并发写入的入口。

- `Chassis_Get_Odometry(out)`：复制最近位姿和有效状态。估计无效时仍返回最后位姿并将 `valid` 置 0，函数返回 0；空指针也返回 0。调用方必须检查有效性，不能把保留的历史坐标当成本帧位置。
- `Chassis_Reset_Odometry(void)`：返回 `uint8_t`，清零平移位置和历史基线。只有底盘失能或三轮已经确认停车时允许重置，运动中拒绝。重置后的首个有效 IMU 航向保留 INS 原有零参考，不把当时车头方向重新定义为零；平移原点可以重置，坐标轴仍按 INS 零向。
- `Chassis_Distance_Start(direction, distance_m, speed_limit_mps)`：保留原调用形式，起步还要求有效里程计。其余待命、使能、姿态和转向尾段衔接条件以 [chassis.h](../project/Core/Control/Chassis/chassis.h) 为准。

位姿当前由 STM32 本地接口读取，未增加 USB 位姿帧或 ROS `odom` 发布。Jetson 继续使用现有动作与到达握手。

## 单段定距闭环

接受动作时保存起始位姿和本段目标方向。进度是估计位移沿固定目标方向的有符号投影，不是累计路径长度；横向漂移或原地转向不能被当作沿目标轴前进。转向剩余不超过 5° 时接定距，仍保留原转向终点航向并由现有航向 PID 修偏。

| 参数 | 当前值与含义 |
| --- | --- |
| 最短请求距离 | 0.010 m，小于该值拒绝 |
| 位置到位容差 | 0.003 m，软件估计位置的判据 |
| 位置比例增益 | 2.0 s⁻¹，根据剩余位移生成速度约束 |
| 合速度上限 | 沿用本段请求限速，最高 0.50 m/s |
| 加减速度上限 | 沿用 0.75 m/s² |
| 制动速度约束 | 根据实测剩余距离限制为 `sqrt(2*a*remaining)` |
| 无进展期限 | 连续 1500 ms 无有效进展进入故障制动 |
| 总时限 | 原理想限速轨迹时间的 3 倍加 2000 ms |
| 到位停车期限 | 发零速后 500 ms 内仍未确认停稳则失能 |

进入位置容差后发零速，继续核对位置直到收到三组新的三轮停车反馈；停车确认前位置重新越界也判为故障。反馈失效、无进展和总时限到期均按异常制动后失能处理，不能视为正常完成，不能用它们放行自动搬运的到达握手。

这是沿指定方向的单段定距控制。3 mm 是估计值的到位门槛，不代表轮胎与地面之间已有 3 mm 定位精度；横向误差、打滑、轮径与齿比误差、六轴航向漂移仍须实测。不能仅凭里程计数值判断越障或搬运真实位置正确。

## 配置与既有动作

`JETSON_AUTO_ENABLED` 默认仍为 0。`JETSON_AUTO_SAFETY_STRAIGHT_M`、`JETSON_AUTO_ROI_BACK_M`、`JETSON_AUTO_RECOVERY_BACK_M` 继续留 0，须实车测定并满足最短请求距离后才启用自动流程。Jetson 的 `gripper.move_s` 仍留空。现有轮序、方向、齿比、速度/航向增益、1.8 kg 前馈和摩擦补偿保持原配置。

安全区先视觉对准、停稳，再按配置的里程计距离锁航向直行；进入该段后仍不使用后续识别结果修正路线。类型 18 仍须正常定距完成并确认停车后发送。盲推和放货后退沿用原限时速度动作，本轮不将这些定时动作改成定距。

## 实车复核

1. 保持自动关闭，先架空验证轮序、方向和单位：前后与左右平移的估计方向应一致，纯旋转不应产生明显平移。确认断反馈、异常状态和 IMU 失效会使里程计无效，并按现有控制逻辑停车。
2. 在已确认停车后重置平移原点，保持车辆静止读取位姿，核对静态漂移及 IMU 航向。再在平整场地低速、空载执行已量好的直线距离，分别记录估计位移、尺量位移和停车余量。
3. 分别重复前后、左右、四个斜向和转向尾段接定距。复核位置到位后到三轮实际停转之间的位移，确认原地旋转、横向漂移和反馈重复不能误报距离完成。
4. 加入实际地面、负载和减速带条件，复测轮滑、姿态漂移、制动与无进展处理。确认控制精度和停车效果后，再填写三段自动距离并按 [板间联调流程](JETSON_USB_TEST.md)验收完整搬运。

历史记录中的指令积分、旧停车距离和用时只属于当时版本；本轮新增反馈闭环须重新进行以上板端复核。
