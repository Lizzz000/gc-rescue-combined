# 代码优化与验证（2026-11-17）

本轮先将干净的本地 `main` 从 `12c8dd5` 快进到云端 `62086f9`，再以该版本为基线优化安全区内沿扫描和 STM32 USB 接收缓冲区。

## 改动

- 安全区 `fitInnerQuad()` 对同一掩膜的三条内沿共用一次非零包围框计算，并跳过包围框外已经确定全零的扫描前缀。左右扫描仍止于各自半区，连续两像素取证、独立行列采样、拟合与准入门槛保持原值。
- STM32 USB 接收按环尾分为至多两次 `memcpy`，整包复制后一次更新 `head`。保持 1023 字节容量、溢出清环、缓冲区代数与计数语义；空输入不访问数据指针。
- USB 同步仍依赖现有单生产者和任务临界区：接收在 USB 中断内，任务读取在 `taskENTER_CRITICAL()` 内。USB 中断优先级为 6，FreeRTOS 屏蔽门槛为 5。本轮没有改动并发模型。

主机使用 Windows、CLion MinGW GCC；固件使用 ARM GNU 15.3.1。测试与构建产物保留在本地忽略目录，不纳入版本控制。USB 的 Cortex-M4 `-Os` 汇编核对确认，正常接收时的 `head` 访问从每字节两读一写减少为整包一读一写；这不代表已经测得板端中断耗时。

内沿差分覆盖 10 种奇偶宽度、4 种高度，含空掩膜、矩形、孤立噪点、断列、有无 Lab 色度图与缺紫侧重拟合。两份结果的 SHA-256 都是 `3BCA31ACA427C0C423002CD99202C7F7C3363AD66C1C8AF5F6B84E7EC3CB8A05`。本机源码快照、差分程序和结果保存在 `Jetson/outputs/code_optimization_20261117`，STM32 回归日志保存在 `STM32/outputs/code_optimization_20261117/native.log`。

OpenCV 4.13.0 同机完整矩阵的处理耗时中位数从 1.81 ms/帧变为 1.78 ms/帧，差值约 1.7%，幅度较小。包含合成造图和真值判定的矩阵总时间分别为 152.85 s、153.97 s。本轮确认了重复扫描减少和输出等价，不据此宣称显著帧率提升；实际 Jetson 收益仍须板端测量。

固定基线场景 `--case-index 0` 交替运行六轮，丢弃首轮预热后，中位数为 2.09 → 2.06 ms/帧，约下降 1.44%；静止序列为 1.96 → 1.97 ms/帧。多项计时均只显示小幅波动。复测日志为上述输出目录的 `fixed-scene-timing.log` 和 `fixed-scene-timing.json`。

安全区检查合计原版 **3405 通过、7 失败**，优化版 **3419 通过、7 失败**。优化版几何专项单独运行，其余八套用 CTest 运行；与原版同名检查的结果一致。已有失败为：矩阵的高光压中线、远视角、低对比和 2 cm 黑块贴线四项有效率不足，黑带的两项运动模糊误差超限，以及几何的一项困难光照有效率不足。本轮没有修复这些识别边界，也没有放宽判据。

## 验证边界

本轮没有连接或烧录 STM32，没有运行真实 USB、相机、ROS/TensorRT/GPU 或机器人运输。主机结果与交叉编译不能替代板端时序、实拍回放和实车验收。运动参数、待标定距离、夹爪时间及自动模式开关均保持原配置。
