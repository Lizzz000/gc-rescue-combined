# CAN 协议（提交 6a 涉及的事实）

本文是 Jetson 侧 **250 ms** 与 **3.45 s** 的唯一来源。代码中的命名常量注释指向本文件。未列入的报文、时间量和流程说明留给提交 10。

## 帧表

| ID | 方向 | DLC | 布局 |
|---|---|---|---|
| 0x17F | Jetson → STM32（手动） | 7 | `data[0]=valid`（必须为 0 或 1）；`data[1..2]=vx`、`data[3..4]=vy`、`data[5..6]=wz`（int16 小端，单位见既有速度定点）。与自动 0x180 **不共用**编解码路径；不得使用 DLC 8。 |
| 0x180 | Jetson → STM32（自动心跳） | 8 | `data[0..6]` 布局与改前的 7 字节心跳相同：`data[0]=valid`（必须为 0 或 1），`data[1..6]` 为 vx/vy/wz 三个 int16 小端。任务在线时生产路径 `valid=0`、速度全零。`data[7]` 为通用 **pause**，整字节只取 0 或 1。 |
| 0x180 | Jetson → STM32（任务失联） | 0 | 空载荷。表示任务失联，不是 pause。 |
| 0x190 | Jetson → STM32 | 1 | 到达应答：`data[0]=1` 受理，`=0` 拒绝。不表示 ROI 已通过。 |
| 0x191 | Jetson → STM32 | 3 | ROI 结果：`data[0]=valid`，`data[1]=passed`，`data[2]=destination`（0 未定／1 左／2 右）。通过时目的区必须为 1 或 2。 |
| 0x192 | Jetson → STM32 | 6 | 命令回执：`data[0]=accepted`，`data[1]=command`（1–5），`data[2..5]=token`（uint32 小端）。命令 1 转向完成、2 安全区到达、3 开始重找、4 投送完成、5 到点受理。命令 3 与命令 5 的 token 为 0。命令 5 **不是**开合到位，只表示已受理 0x208。 |
| 0x193 | Jetson → STM32 | 6 | 去程转向授权：`data[0]=1`，`data[1]=destination`（1 左／2 右），`data[2..5]=token`。 |
| 0x208 | STM32 → Jetson | 1 | 通用「到点」：`data[0]=1` 夹取点，`=2` 释放点。沿用既有请求/重发；回执为 0x192 命令 5、token 0。同 kind 重发只再交命令 5、不再开合；夹取完成后同一轮的 `=2` 按新请求处理；在途时不同 kind 丢弃；0x205 清空。 |

手动 0x17F 由 `teleop_pkg` 独立封装；自动 0x180 由 `bridge_pkg` 的 `CanProtocol::velocity` 在写出前编码。二者不得共享会把 DLC 8 漏进 0x17F 的编解码。

## 链路超时 250 ms

STM32 在 250 ms 内未收到合法自动心跳（或中心帧超过该期限）即按链路超时处理。心跳停发只走这一期限，不另增时间量。0x193 重授间隔与此 **同一 250 ms**。

## 请求期限 3.45 s

STM32 停稳后首次尝试提交请求时起算（含发送邮箱等待），单一 3.45 s；提交前的停稳等待由 STM32 制动/停稳期限覆盖，不计入；Jetson 收到帧后最多 3.0 s（`bridge.request_timeout_s`）回复。0x208 的 3.45 s 只覆盖到点回执，开合时间不计入。Jetson 不持有这条 CAN 截止。

## 放行规则

所有回复（0x190、0x191、0x193，以及 0x192 命令 1–5）只算受理，不放行运动。STM32 在该回复之后收到的第一帧合法 DLC 8、`pause=0` 的心跳且底盘停稳后，才开始下一动作。等待期间不重发、不计入 3.45 s。心跳停发只走既有 250 ms 链路超时。
