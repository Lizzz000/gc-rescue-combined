# 板间帧

板间链路是 STM32 USB OTG FS 设备。Jetson 主机打开 `link.device`。引脚 PA11 D-、PA12 D+、PA10 OTG ID，全速 12 Mbit/s，没有 ULPI，不是 480 Mbit/s。

线上帧：`A5`、版本 `01`、类型 uint8、长度 uint8、载荷、CRC-16/IBM 小端。CRC 覆盖版本、类型、长度和载荷，不覆盖 `A5`。最大载荷 8。电机仍在 STM32 的 CAN1，Jetson 不驱动电机。

长度：类型 1 为 8，类型 2 为 7，类型 3 和 4 为 8，类型 5 为 1，类型 6 为 3，类型 7 和 8 为 6，类型 16、19、21 为 1，类型 17、18、20 为 5。无硬件验收使用伪终端传送同样的 USB 帧。

本文是 Jetson 侧 **250 ms** 与 **3.45 s** 的唯一来源。代码中的命名常量注释指向本文件。

## 类型

| 类型 | 方向 | 含义 |
|---|---|---|
| 1 | Jetson → STM32 | 心跳。载荷依次为 `alive`、`pause`、三轴 int16 小端。`alive=0` 表示失联，不是 pause，也不是少一帧。`pause` 整字节只取 0 或 1。自动搬运不由这三轴下发速度。 |
| 2 | Jetson → STM32 | 手动速度。`valid` 必须为 0 或 1，随后 `vx`、`vy`、`wz` 三个 int16 小端（×1000）。不带 pause，也不表示任务失联。与类型 1 不共用编码。 |
| 3 | Jetson → STM32 | 目标中心。 |
| 4 | Jetson → STM32 | 安全区中心。 |
| 5 | Jetson → STM32 | 到达应答：载荷 `1` 受理，`0` 拒绝。不表示 ROI 已通过。 |
| 6 | Jetson → STM32 | ROI 结果：`valid`、`passed`、`destination`（0 未定／1 左／2 右）。通过时目的区必须为 1 或 2。 |
| 7 | Jetson → STM32 | 命令回执：`accepted`、`command`（1–5）、`token`（uint32 小端）。命令 1 转向完成、2 安全区到达、3 开始重找、4 投送完成、5 到点受理。命令 3 与命令 5 的 token 为 0。命令 5 不是开合到位，只表示已受理类型 21。 |
| 8 | Jetson → STM32 | 去程转向请求：`1`、`destination`（1 左／2 右）、`token`。 |
| 16 | STM32 → Jetson | 到达。载荷 `01`。 |
| 17 | STM32 → Jetson | 转向完成。载荷 `01` 加 token。 |
| 18 | STM32 → Jetson | 安全区到达。载荷 `01` 加 token。 |
| 19 | STM32 → Jetson | 重找。载荷 `01`。 |
| 20 | STM32 → Jetson | 投送。载荷 `01` 加 token。 |
| 21 | STM32 → Jetson | 到点：`1` 夹取点，`2` 释放点。回执为类型 7 命令 5、token 0。同一种类重发只再交命令 5、不再开合；夹取完成后同一轮的 `2` 按新请求处理；在途时不同种类丢弃；类型 19 清空。 |

类型 3、4：`valid`、`x`/`y` 两个 int16 小端（×10000）、源帧时间低 24 位毫秒。无效时载荷清零。同一源帧的重发不重复用于滤波或到位确认。

类型 2 由 `teleop_pkg` 封装。类型 1 由 bridge 在写出前编码。二者不得共用一条会把 pause 写进类型 2 的路径。

多字节字段小端。`vx`/`vy` 是车体前/左，单位 m/s，定点值除以 1000；`wz` 俯视逆时针为正，单位 rad/s，也除以 1000。中心除以 10000 得图像归一化位置，不是距离，也不是轮速。token=0 合法。

## 链路超时 250 ms

STM32 在 250 ms 内未收到合法类型 1（或中心帧超过该期限）即按链路超时处理。心跳停发只走这一期限。类型 8 的重授间隔与此同一 250 ms。`alive=0` 立即按失联处理，不等这 250 ms。

## 请求期限 3.45 s

STM32 停稳后首次尝试提交请求时起算（含提交等待），单一 3.45 s。提交前的停稳等待由制动和停稳期限覆盖，不计入。Jetson 收到帧后最多 3.0 s（`bridge.request_timeout_s`）回复。类型 21 的 3.45 s 只覆盖到点回执，开合时间不计入。Jetson 不持有这条截止。

## 放行规则

类型 5、6、8，以及类型 7 的命令 1–5，只算受理，不放行运动。STM32 在该回复之后收到的第一帧 `alive` 非 0 且 `pause=0` 的类型 1，并且底盘停稳后，才开始下一动作。等待期间不重发、不计入 3.45 s。心跳停发只走 250 ms 链路超时。
